batch token. It also adds cancellation coverage and documentation, exposes core internals to the
Operations test assembly, and suppresses two compiler naming warnings. The revised README correctly
distinguishes child-only cancellation results from parent or supplied-token cancellation exceptions.

## Open questions

- The prior report's mixed Shell failure/cancellation precedence concern remains unconfirmed.
  The new cancellation check precedes HRESULT error propagation. Establishing a defect would require
  a native reproduction where a distinct earlier failure survives in `PerformOperations`' result
  while a later callback reports cancellation, together with a required precedence contract.
  No such reproduction or contract was established, so this is not a numbered finding.
- Cancellation while waiting for a busy STA pool was not separately reproduced. The installed pool
  documentation promises cancellation before dispatch, but does not specify the exception token for
  that path. The already-canceled and callback-cancellation paths are covered and passed. A bounded
  single-worker queue experiment would resolve the remaining token-documentation uncertainty.
- No new end-to-end run through a real Brows.Operations operator or baseline red/green regression
  experiment was performed. Operation-tree classification was verified against the exact dependency
  source and public contract; current-target cancellation behavior was verified by existing tests.
