## Findings

### #1 [P3] The fallback comment incorrectly says the query is NTFS-only [Resolved]

- Status: Resolved
- Location: `source/Brows.Win32.Interop/Win32/Win32KernelService.cs:53-56`
- Problem and trigger: The new comment describes NTFS as the sole implementation of
  `FileCaseSensitiveInformation`. A directory on ReFS is a counterexample.
- Impact: The comment gives maintainers an incorrect explanation of the native result they
  will see when diagnosing a ReFS or Dev Drive directory. The method itself queries the handle
  and honors successful responses from ReFS.
- Evidence: Using the target build's existing Win32 declarations, a query on the repository's
  ReFS directory returned `STATUS_SUCCESS`, four bytes of information, and a zero flags value.
  The public method returned `false`, consistent with the observed flags. Microsoft also
  documents per-directory case sensitivity on ReFS.
  [Microsoft ReFS documentation](https://learn.microsoft.com/en-us/windows-server/storage/refs/refs-registry-values#dev-drive-and-case-sensitivity-settings)
- Suggested resolution: Describe the fallback in terms of what file systems and redirectors can
  return when they reject this information class. Remove the NTFS-only claim.
- Verification: Confirm the revised comment agrees with the observed ReFS success and the
  fallback cases covered by `CaseSensitiveQueryIsUnsupported`.

Resolution: The comment in `CaseSensitiveQueryIsUnsupported`
(`source/Brows.Win32.Interop/Win32/Win32KernelService.cs:52-57`) no longer claims that only NTFS
implements the query. It now describes the fallback by what file systems that do not implement the
query return: `STATUS_INVALID_PARAMETER` from the FAT driver, and `STATUS_INVALID_DEVICE_REQUEST`
from other file systems and redirectors. Behavior is unchanged.
Verification: The change is comment-only, so no regression test applies. On the repository's ReFS
volume, `fsutil file queryCaseSensitiveInfo F:\dev\me\brows-win32-interop` reported the attribute
as disabled, confirming that ReFS implements the query, consistent with the revised comment. The
statuses the comment names match the cases `CaseSensitiveQueryIsUnsupported` handles.
`dotnet build` of `Brows.Win32.Interop` passed with zero warnings and errors, and
`dotnet test tests/Brows.Win32.Interop.Tests --filter FullyQualifiedName~CaseSensitive` passed
9 tests on each of `net462`, `net48`, `net8.0-windows`, and `net10.0-windows`. `git diff --check`
passed.
